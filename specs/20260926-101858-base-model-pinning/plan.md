# Implementation Plan: Base Model Selection and Pinning

**Branch**: `20260926-101858-base-model-pinning` | **Date**: 2026-09-26 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/20260926-101858-base-model-pinning/spec.md`

## Summary

Implement the P0-8 model-identity pinning contract: create `models.yaml` as the eighth spec artifact, a dedicated `tools/models_validator.py` implementing checks FV-SPEC-089 through FV-SPEC-095, a matching `tests/test_models_spec.py` with synthetic fixtures, and the necessary updates to `tools/validate_spec.py` (new `models` scope) and `tools/freeze.py` (eighth artifact). All checks follow the `access_profile_validator.py` pattern — a `validate_models_spec()` entry point returning `(bool, dict)`, dispatched by `validate_spec.py`.

**Constraints**: No GPU, no network; fail closed on missing or malformed inputs
**Scale/Scope**: 2 model roles (blocks_0_2, block_3_confirmation); 7 validation checks; ~6 fixture files

### Step 1 — Create `.factverify/spec/models.yaml` (skeleton)

Create the eighth spec artifact with all DECISION_REQUIRED placeholders and staged `block_3_confirmation`.

**File**: `.factverify/spec/models.yaml`

```yaml
# .factverify/spec/models.yaml
# P0-8 — Model identity pinning
# SPEC ARTIFACT — do not edit after spec-v1 without an amendment record.
# Blocking decisions: D-46 (Blocks 0-2 model), D-47 (Block 3 model),
#                    D-48 (dtype/precision), D-49 (base vs instruct)

roles:
  blocks_0_2:
    repo_id: DECISION_REQUIRED         # D-46
    model_revision: DECISION_REQUIRED  # D-46 — must be 40-char hex commit SHA
    tokenizer_revision: DECISION_REQUIRED
    variant: DECISION_REQUIRED         # D-49 — "base" or "instruct"
    dtype: DECISION_REQUIRED           # D-48 — e.g. "float32" or "bfloat16"
    licence: DECISION_REQUIRED         # D-46 — SPDX id or "custom:<url>"
    files: {}                          # sha256 digests — populated after download

  block_3_confirmation:
    status: pending                    # staged commitment — D-47
    deadline: null                     # set before P6; required when status: pending
    repo_id: DECISION_REQUIRED
    model_revision: DECISION_REQUIRED
    tokenizer_revision: DECISION_REQUIRED
    variant: DECISION_REQUIRED
    dtype: DECISION_REQUIRED
    licence: DECISION_REQUIRED
    files: {}
```

### Step 3 — Create `tools/models_validator.py`

Implement FV-SPEC-089 through FV-SPEC-095. Structure mirrors `access_profile_validator.py`:

```
tools/models_validator.py
├── Constants: IMMUTABLE_REVISION_RE, REQUIRED_ROLE_FIELDS, SHA256_FILE_RE
├── load_models_spec(spec_root) → dict           # load + parse models.yaml
├── check_fv_spec_089_identity(roles) → list     # completeness
├── check_fv_spec_090_revision(roles) → list     # immutable revisions
├── check_fv_spec_091_digests(roles, model_dir) → list  # file integrity
├── compute_identity_hash(role_entry) → str      # canonical hash
├── check_fv_spec_092_access_profile(roles, profile_path) → list
├── check_fv_spec_093_identity_hash(roles) → list  # definition check
├── check_fv_spec_094_downstream(roles, downstream_report) → list
├── check_fv_spec_095_amendment(spec_root, checksums_path, prereg_path) → list
├── write_models_report(...) → dict
└── validate_models_spec(spec_root, ...) → (bool, dict)
```

**Key implementation notes:**

- `check_fv_spec_089_identity`: for each role, if `status == "pending"`, all field checks are `pending`. Otherwise, check each required field is non-null, non-empty, and not `"DECISION_REQUIRED"` (strict) or not null (non-strict).
- `check_fv_spec_090_revision`: `re.fullmatch(r"[0-9a-f]{40}", value)`. Skip roles with `status == "pending"`.
- `check_fv_spec_091_digests`: if `model_dir is None`, return `[{"status": "pending", ...}]`. Otherwise, walk the `files` dict, re-compute SHA-256, compare. Also check for extra/missing files.
- `compute_identity_hash`: `json.dumps({"repo_id":..., "model_revision":..., "tokenizer_revision":..., "dtype":..., "adapter_digest": None}, sort_keys=True, ensure_ascii=False)` → `sha256:` + hexdigest.
- `check_fv_spec_092_access_profile`: load `access_profile.md` via `yaml.safe_load`. If absent → `pending`. For each intervention requiring `fine_tune` or `export_checkpoint`, verify `licence` does not contain `"api_only"`.
- `check_fv_spec_093_identity_hash`: run `compute_identity_hash` for each resolved role; collect results. If any role is unresolved, that role's hash is `pending`.
- `check_fv_spec_094_downstream`: if no downstream report path → `pending`. Parse JSON, extract `model_identity_hash`, compare against computed hash. Ledger + cache checks are always `pending` at this phase.
- `check_fv_spec_095_amendment`: read `CHECKSUMS.sha256`; extract recorded digest for `models.yaml`. Compare against current SHA-256. If mismatch: scan `preregistration.md` for an amendment block referencing `models.yaml`. Fail if none found.

### Step 7 — Create `tests/test_models_spec.py`

Seven test functions, one per FV-SPEC-089 through FV-SPEC-095:

| Function | Tests |
|---|---|
| `test_fv_spec_089_identity` | Complete entry passes; missing field fails; pending role passes; DECISION_REQUIRED fails in strict mode |
| `test_fv_spec_090_immutable_revision` | 40-char hex passes; "main" fails; short hash fails; absent fails |
| `test_fv_spec_091_file_digests` | Correct dir passes; modified file fails; missing file fails; extra file fails; absent dir → pending |
| `test_fv_spec_092_access_profile` | Compatible model passes; absent profile → pending; api_only licence under fine_tune intervention fails |
| `test_fv_spec_093_identity_hash` | Identical inputs → identical hash; single-field change → different hash; hash is byte-identical across two calls |
| `test_fv_spec_094_downstream_binding` | Matching hash passes; mismatched hash fails; absent report → pending |
| `test_fv_spec_095_amendment` | No checksums → pending; matching checksums passes; changed yaml + amendment passes; changed yaml + no amendment fails |

Each function uses `assert check_fn(...) == []` for pass cases and `assert len(check_fn(...)) >= 1` for fail cases.
